# Release highlights

- The CLI, dashboard, and SDK now use the Rachet name and enrollment terms throughout; the dashboard lists enrollments, explains why a run ended, and supports pausing, resuming, or cancelling active runs.
- Marketing workflows require recorded consent and include a managed unsubscribe link and mailbox one-click action. An opt-out stops later marketing across the workspace.
- Resend setup now includes the marketing sender and unsubscribe details. Preference history identifies the email and workflow behind a link opt-out.
- **Self-hosted deployment:** `scripts/deploy.sh` users should rerun the same command; it adds `UNSUBSCRIBE_SIGNING_KEYS` and `UNSUBSCRIBE_SUPPORT_EMAIL` and runs the migrations. For Compose or Coolify, configure both variables in API, worker, and dispatcher before deploying. Generate the signing key with `openssl rand -base64 32`, keep the same value across services, back it up, and set the support email to a monitored address. Compose applies migrations automatically; for split Coolify deployments, run `node dist/apps/server/db/migrate.js` on the API app before deploying all three services from this release. Then have each workspace admin configure the marketing sender and support details in **Integrations → Email → Resend**.
- **Existing workflows:** Review each workflow's explicit `transactional` or `marketing` purpose and republish before its next send. Older workflow versions have no recorded purpose review, so their sends pause until republished. No other breaking changes.
