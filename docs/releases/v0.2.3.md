# Rachet v0.2.3

## Features

- The CLI, dashboard, and SDK use the Rachet name. The dashboard lists enrollments, explains why runs ended, and lets operators pause, resume, or cancel runs.
- Marketing workflows record consent, add one-click unsubscribe, stop later marketing after opt-out, and show the email and workflow behind a link opt-out.
- Email provider settings now include the marketing sender and unsubscribe support details.

## Breaking changes

- Existing workflow versions have no recorded email-purpose review. Set each workflow to `transactional` or `marketing` and republish it; sends pause until then.
- Production deployments require `UNSUBSCRIBE_SIGNING_KEYS` and `UNSUBSCRIBE_SUPPORT_EMAIL`. The deploy script adds these automatically; manual deployments must set them for the API, worker, and dispatcher.

## Upgrade steps

1. If you installed with `scripts/deploy.sh`, rerun your existing command. It adds missing settings and applies migrations.
2. For Docker Compose, generate a signing key with `openssl rand -base64 32`. Set `UNSUBSCRIBE_SIGNING_KEYS` to that value and `UNSUBSCRIBE_SUPPORT_EMAIL` to a monitored address in `.env.local`. Keep the signing key stable and back it up. Build and start the stack with `docker compose --env-file .env.local build` and `docker compose --env-file .env.local up -d`; Compose applies migrations automatically.
3. For split Coolify deployments, set both variables for the API, worker, and dispatcher. Use the same signing key in all three and back it up. Run `node dist/apps/server/db/migrate.js` on the API app as its pre-deployment command, then deploy all three services from this release.
4. For each workspace that sends marketing, have an admin configure the marketing sender and support details in **Integrations → Email → Resend**. Review and republish every existing workflow with its explicit email purpose before its next send.
