## Features

- Send one plain-text email through MCP with `message_send` or through the CLI with `rachet call message.send`. Use your workspace sender without creating a template or journey. Marketing sends require recorded consent and include an unsubscribe link.
- Connect Amazon SES for workflow and one-off email. Rachet records events from Amazon SNS and blocks later sends after a permanent bounce or complaint.
- Update dependencies used by the server, dashboard, and CLI.

## Breaking changes

- None.

## Upgrade steps

1. Back up the Rachet and Temporal PostgreSQL databases and the integration encryption key. Keep the existing database, Temporal, sender, and unsubscribe settings. This update requires no new environment variables.
2. Deploy v0.2.7. If you use the one-host installer, rerun `./scripts/deploy.sh rachet.example.com admin@example.com` with your existing hostname and administrator address. If you manage the services separately, build the v0.2.7 images and run `node dist/apps/server/db/migrate.js` once from the new app image. Confirm it applied `0014_standalone_email.sql` and `0015_amazon_ses.sql` before starting the app, dispatcher, and worker from the same version. See the [deployment guide](https://github.com/socialrobot-io/rachet/blob/v0.2.7/docs/DEPLOYMENT.md).
3. Existing Resend workspaces keep their provider. To use Amazon SES, follow the [Amazon SES setup guide](https://github.com/socialrobot-io/rachet/blob/v0.2.7/docs/AMAZON_SES.md) to configure a verified sender, IAM credentials, and SNS. Confirm the SNS subscription and send a test to activate SES.
