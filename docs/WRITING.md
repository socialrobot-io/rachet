# Writing for Rachet

Write for the person who must use the document. State the action, decision, or constraint first. Delete background detail that does not help that person.

Use these rules for README files, guides, user-facing UI copy, and documentation changes:

- Use short, common words and direct sentences.
- Use active voice unless the actor is unknown or unimportant.
- Give one instruction or fact per sentence. Put conditions before the step they affect.
- Use one term for one thing. Define a technical term the first time it is needed.
- Prefer a numbered procedure or a table to dense prose.
- Include implementation detail only when it changes setup, use, safety, or troubleshooting.
- Delete filler, sales claims, throat-clearing, vague promises, and repeated warnings.
- Do not use worn metaphors, jargon when plain English works, or a long word when a short one works.
- Break any style rule rather than write unclear, ungrammatical, or misleading text.

This is a practical house style based on [ASD-STE100 Simplified Technical English](https://www.asd-ste100.org/) and George Orwell's six rules in [*Politics and the English Language*](https://www.orwellfoundation.com/the-orwell-foundation/orwell/essays-and-other-works/politics-and-the-english-language/). It is not a claim of formal ASD-STE100 compliance; that standard also requires its controlled dictionary.
